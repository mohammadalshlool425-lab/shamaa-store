# المراحل ومعايير القبول

## قاعدة التنفيذ

يُنجز كل نطاق ويُختبر قبل إضافة خدمات مالية أو ميزات أوسع. كلمة «مُنفّذ» تعني وجود مسارات وبيانات وصلاحيات وتدفق يعمل محليًا؛ **لا تعني نشر إنتاج أو اعتماد قانوني/أمني**. دليل الاختبارات الفعلي في [VERIFICATION.md](VERIFICATION.md).

## المرحلة 1 — الأساس الحالي

| النطاق | المنفذ بالفعل | الحد الواضح / القبول |
|---|---|---|
| الهوية والتصفح | شمعة، AR/EN، اكتشاف اللغة وزر تبديل، RTL/LTR، هاتف/كمبيوتر، بحث/تصنيف/ترتيب/صفحات، متاجر وتفاصيل منتجات | بحث SQL محدود، لا محرك اقتراح ذكي أو توقعات سوق |
| الإتاحة | تسميات نماذج، رسائل خطأ، تركيز ولوحة مفاتيح وحوار، تباين وأهداف لمس، 320px و200% نص، axe على تدفقات مختارة | ليست شهادة WCAG 2.2 AA كاملة؛ قارئات الشاشة وiOS/Firefox/Safari تحتاج تحققًا يدويًا |
| الحساب | تسجيل ودخول وخروج حقيقي، scrypt، جلسات وإبطال، تأكيد بريد واستعادة كلمة مرور، إشعارات | file transport محلي؛ SMTP/TLS منفذ ومختبر بنقل وهمي في الاختبارات، لا إرسال حقيقي إلى مزود خارجي هنا |
| البائع | بريد مؤكد → طلب متجر → مراجعة مدير، متجر مستقل ببيانات AR/EN ولون/مدينة/شحن، صور ومنتجات وتعديل وإيقاف ومخزون | متجر واحد وبحد 10 منتجات أولية؛ صورة واحدة؛ لا مستندات/شارات هوية متقدمة أو إدارة موظفين |
| السلة | زائر محلي بالمعرفات والكميات، دمج بعد الدخول، سلة محفوظة على الخادم | ليست حجزًا للمخزون؛ المفضلة محلية للجهاز فقط |
| الطلب | عرض محسوب، تقسيم حسب البائع، شحن لكل متجر، خصم ذري، مفتاح تكرار واستعادة محاولة، COD، سجل حالات، إلغاء ورد المخزون | لا مزود توصيل، ولا تأكيد قبض نقد أو مرتجعات بعد الشحن |
| العمولة | عام/فئة/أم/متجر، تقريب صحيح ولقطة ثابتة، ledger مستحق عند التسليم مرة واحدة | لا محفظة/صرف/تحويلات/مطابقة نقد/ضرائب آلية؛ التخصيص الترويجي محدد يدويًا وليس مؤقتًا آليًا |
| الإدارة | MFA فعلي، مراجعة متاجر/منتجات، تعليق مستخدم وإبطال جلساته، طلبات وسجلات وإعدادات، reauth للمال | لا ترقية أدوار من العميل، ولا فصل اعتمادين لدفعات لأن نظام الدفعات غير مفعّل أصلًا |
| PWA | manifest وأيقونات، cache موارد/كتالوج عام، صفحة خاصة offline، منع تنفيذ شراء/مخزون دون اتصال | HTTPS أو localhost؛ لا APK ولا ضمان تثبيت كل متصفح؛ وسائط البائعين ليست مخزنة offline |
| الأمان | SQL binding، CSRF/Origin، cookies، حدود رفع/صور، rate limits للحساب/الطلب، CSP/host guards، سجلات append-only | لا اختبار اختراق مستقل أو حماية DDoS مُدارة أو تفويض متعدد المؤسسات |
| النسخ | قاعدة ووسائط مرجعية في أرشيف AES-GCM، استعادة لوجهة جديدة، فحص القاعدة وإبطال الجلسات، تدوير احتفاظ | أداة جدولة وقوالب systemd موجودة؛ **التفعيل والنسخ الخارجي الفعلي غير منجزين** |
| الخصوصية/القانون | عدم تتبع، حجب بيانات الحساب عن الكتالوج، مسودات واضحة وحدود جمع | لا زر تصدير/حذف ذاتي، ولا موافقات قانونية/ضريبية أردنية معتمدة أو فواتير رسمية؛ إجراءات وإعدادات إطلاق لاحقة |

### بوابة قبول التطوير للمرحلة الأولى

- [x] إنشاء وقراءة البيانات الفعلية في قواعد معزولة؛ لا صفحات تعتمد فقط على بيانات JavaScript مصطنعة.
- [x] اختبار عمولات/تقريب/أسعار/شحن وتقسيم وتكرار الطلب.
- [x] اختبار شراء متزامن ضد آخر وحدة، وفشل معاملة دون طلب/خصم جزئي.
- [x] اختبار ملكية المنتجات/الصور/الشحنات والطلبات ومنع دور عميل مزور.
- [x] اختبار MFA وحواجز الإدارة وإعادة المصادقة المالية.
- [x] اختبار نسخ/استعادة بوسائط، مفتاح خطأ وعبث وعبور مسارات، ثم تدوير احتفاظ.
- [x] تدفقات متصفح في اللغتين وعلى الهاتف، واختبارات axe وoffline/عدم تخزين الخاص.
- [ ] قبول الإنتاج: نطاق وTLS وSMTP فعلي وتسليم بريد، نسخ مجدولة خارجية واستعادة تشغيلية، سياسات واتفاق بائع ومراجعة قانون/ضرائب، تشغيل ومراقبة وحماية المضيف. **لم تنجز في هذه الجلسة**.

## المرحلة 2 — اكتمال السوق والخدمة

تنفذ في دفعات صغيرة، لا تضاف كلها كتبديل إعداد واحد:

1. **المستعمل والرقمي:** condition واضح ومراجعة، ملفات خاصة ومفاتيح/صلاحيات تنزيل من الطلب، فحص ملفات وحدود تنزيل وروابط موقعة وانتهاء، وسياسة استرداد واقعية. لا تعرض «منتج رقمي» قبل تأمين الوصول. القبول: شخص آخر/رابط منتهي/طلب غير مؤهل لا ينزل الملف؛ لا تسريب تخزين عام.
2. **كتالوج ومخزون أوسع:** متغيرات وSKU فرعي، صور متعددة، مواقع/حجوزات/حد تنبيه واستيراد CSV بمرحلة معاينة. القبول: طلب متغير واحد لا يخصم متغيرًا آخر، والاستيراد قابل للتحقق والتراجع.
3. **تفاعل وخدمة:** رسائل محفوظة ذات صلاحيات، تقييم بعد شراء مؤكد دون تقييمات مولدة، إبلاغ/نزاع/مرتجعات وتتبع أدلة ومهل، قناة دعم حقيقية. القبول: لا يرى شخص محادثة/عنوانًا لا يخصه، والتقييم له طلب مؤهل.
4. **عروض وتشغيل:** كوبونات وحدود تكديس واستخدام ذرية، ولاء وانتهاء، فواتير/إيصالات تشغيلية وتسوية يدوية وتقارير وصادرات. لا وصف الفواتير بأنها رسمية قبل اعتماد متخصص. القبول: تطبيق الاستهلاك والخصم من الخادم مرة واحدة.
5. **نمو وربح:** مواضع إعلانية موسومة، اشتراكات اختيارية، تسويق بالعمولة بروابط وإسناد حقيقي ومكافحة إساءة؛ لا بيع الثقة أو أرقام انتشار مختلقة. القبول: القياس من أحداث حقيقية وموافقة الخصوصية، لا زيادات أرقام شكلية.
6. **حقوق الحساب:** تصدير ذاتي بعد إعادة التحقق وحذف/إخفاء منضبط مع استثناءات حفظ السجلات القانونية ومواعيد إتلاف النسخ؛ مراجعة قانونية وتدقيق صلاحيات التصدير.

## المرحلة 3 — التكاملات الحقيقية

- **الدفع بالأردن:** مقارنة مزودين ودعم JOD والتجار الأردنيين والتسوية والاسترداد والرسوم والتصاريح أولًا. sandbox ثم توقيع webhooks ومنع تكرارها ومصالحة ودفعات فاشلة/معلقة، ثم إنتاج محدود. لا تخزين بطاقات، ولا اعتبار redirect نجاحًا نهائيًا.
- **الشحن:** عقود وأسعار فعلية وتغطية وجغرافيا وwebhooks، فشل/تكرار/إلغاء الملصق وتحديث الحالة؛ لا «ناقل متصل» قبل اختبار طرفه.
- **الصرف والمحاسبة:** أموال محصلة ومطابقة، فترات نزاع/حجز، منع صرف مزدوج، فصل المنشئ والمعتمد، إعادة مصادقة وسجل غير قابل للتلاعب، مراجعة محاسب ومزود مرخص حسب الحالة. لا تحويل بناء على تغيير status وحده.
- **AI اختياري:** adapter مستقل ومعطل افتراضيًا، مفاتيح خلفية، سقف تكلفة وبيانات مصرح بها وموافقات، قابل للاستبدال. مواصفات المنتج من البائع لا من اختلاق AI، ولا حكم احتيال/مال نهائي آلي.
- **SEO/قياس/مخاطر:** تصيير محسن ومراجعة structured data على حقائق فقط، قياس بإذن وحفظ محدود، إشارات اشتباه مع مراجعة بشرية وقابلية اعتراض، لا وعود ترتيب/ربح.

لكل مزود: تحقق مؤرخ من حدود المجاني والشروط التجارية ومعالجة البيانات والتصدير/النسخ، وقائمة تكاليف وموافقة المالك قبل إضافة المفاتيح.

## المرحلة 4 — المؤسسات والتوسع

- PostgreSQL وترحيلات موثقة وقفل معاملات وخطة استعادة، وتخزين كائنات خاص ونسخ متعددة المواقع؛ لا قرص SQLite مؤقت على عدة instances.
- مؤسسات وموظفون بصلاحيات دقيقة ودعوات وإلغاء وصول وفصل مؤسسات ومنح أقل صلاحية؛ اختبارات عزل بين المستأجرين.
- دول وعناوين وتغطية وضرائب/تقريب وعملات متعددة بقيود مالية واختبارات، دون كسر JOD والفلس.
- مهام وطوابير ومراقبة/تنبيهات واختبارات حمل فعلية وموازن بعد إثبات الحاجة؛ خطة كلفة/توقف/تراجع.
- API بإصدار وتوثيق ومصادقة مناسبة لتطبيق Android، ثم تطوير/اختبار وإطلاق متجر تطبيقات مستقل. PWA الحالي لا يعني أن Android الأصلي مكتمل.

## تعريف «انتهت المرحلة»

تغييرات بيانات مرقّمة + صلاحيات خادم + اختبارات قبول/فشل/تزامن مناسبة + مستند تشغيل/استعادة وتكلفة + تجربة RTL/LTR وإتاحة + موافقات خارجية لازمة. الميزات المعطلة/المؤجلة لا تظهر كأزرار دفع أو توثيق أو خدمة وهمية. لا تُعلَن المرحلة التالية مكتملة بمجرد تصميم صفحاتها.
