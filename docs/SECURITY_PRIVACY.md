# الأمان والخصوصية — حدود واضحة قبل الإنتاج

هذه مراجعة تنفيذ وتدفقات، **ليست استشارة قانونية أردنية أو اختبار اختراق مستقل أو شهادة امتثال**. راجع واجهة المساعدة باعتبارها مسودات سياسات، ولا تبدأ جمع بيانات عملاء حقيقيين على معاينة/HTTP تطوير.

## الضوابط الموجودة

- scrypt بكلفة مناسبة للخادم، salt عشوائي، وعدم اقتطاع المسافات من كلمة المرور؛ لا تخزين كلمات المرور كنص.
- جلسات opaque عشوائية؛ تخزين تجزئة الرمز لا الرمز الأصلي، Cookie HttpOnly/SameSite=Lax، وSecure في الإنتاج أو عندما يكون Public URL هو HTTPS (حتى في المعاينة). صلاحية الجلسة الحالية 7 أيام. عرض جلسات الحساب وإبطال جلسة أو الجميع عند إعادة كلمة المرور/التعليق.
- رموز البريد الجديدة تقع في fragment بعد `#token=` فلا تدخل طلب GET أو سجل URL عند الوكيل؛ تُرسل في جسم POST فقط وتُزال من شريط العنوان. الروابط القديمة ذات query مدعومة للتوافق وقد يظهر رمزها في الطلب الأول، فلا تُصدر روابط جديدة بذلك الشكل.
- تأكيد بريد لمدة 24 ساعة وإعادة تعيين لمدة 30 دقيقة، أحادية الاستخدام وتُبطل عند إصدار جديد. لا استهلاك للتأكيد على GET.
- MFA TOTP للمشرف، سر مشفر، منع إعادة استعمال الرمز المقبول وتحديد المحاولات؛ إعادة كلمة مرور + OTP حديث لتعديل المال بعد 10 دقائق. لا recovery codes عامة أو تجاوز تلقائي.
- أدوار وملكية من الخادم، لا role يختاره العميل، وإخفاء عناوين المشترين عن غير المشتري/البائع المعني/المشرف.
- X-Requested-With + تحقق Origin وCSRF مربوط بالجلسة للكتابات، دون CORS عام. استعلامات SQL بمعلمات وحدود وفرز من قائمة مسموحة.
- CSP من نفس النطاق، no-referrer وnosniff وقيود وسائط المتصفح، وhost allowlist. HSTS في الإنتاج فقط.
- جسم طلب حتى 6MiB، صور حتى 5MiB/16Mpx، إعادة فك/ترميز وإزالة metadata، حصة وسائط لكل بائع وملكية لا تعتمد على اسم الملف.
- المعاملات والقيود والتفرد والسجلات append-only لحماية المخزون والطلبات والعمولة؛ هذه ليست حماية من مالك قاعدة خبيث ذي صلاحية نظام كاملة.
- بيانات خاصة `no-store` واستثناء صريح من Service Worker، لا queue كتابات offline. لا trackers أو AI أو مفاتيح مزودين في ملفات الواجهة.
- أدلة التشغيل توقف access logging الكامل في أوامر التطبيق؛ رسائل أخطاء التطبيق لا تعيد المدخلات الحساسة وتكتب نوع العطل/معرّفًا دون body أو query.

## ما يُجمع ولماذا

| البيانات | الغرض والوصول | ملاحظة |
|---|---|---|
| الاسم/البريد/لغة الحساب | دخول وتواصل معاملات؛ المستخدم/المشرف | لا تظهر في كتالوج المنتجات كبيانات حساب |
| تجزئة كلمة المرور وسر MFA مشفر | مصادقة؛ الخادم فقط | لا تُعاد إلى API |
| تجزئة IP وUser-Agent والجلسة | حد محاولات وتنبيه شبكة/جهاز وإبطال جلسات | تجزئة IP **ليست إخفاء هوية مطلقًا**، وUser-Agent وصف مرسل من الجهاز وليس هوية موثّقة |
| الاسم/الهاتف/المدينة/العنوان عند الطلب | إتمام التسليم؛ المشتري والبائع لشحنته والمشرف | ليست مطلوبة لمجرد تصفح الكتالوج |
| معلومات المتجر والمنتج والصور المنشورة | عرض البيع؛ تصبح عامة بعد الموافقة | يجب على البائع امتلاك الحقوق وعدم رفع بيانات خاصة في الصورة/الوصف |
| طلب/مخزون/عمولة وأحداث وتدقيق | سلامة التشغيل والمراجعة والنزاعات | ليس نظام فواتير رسمية أو دفتر محاسبة كامل |
| طابور البريد وملفات .eml التطويرية | نقل المعاملات/فحص التطوير | محتواها حساس وقد يتضمن روابط تحقق؛ لا تنشره أو تتركه يتراكم دون سياسة |
| مفضلة/سلة زائر/لغة محلية | تفضيلات الجهاز؛ معرفات وكميات فقط | لا عناوين أو هواتف في localStorage؛ محاولة طلب في sessionStorage تحفظ المفتاح لا العنوان |

لا تُجمع بطاقات أو مفاتيح بنكية أو وثائق هوية في المرحلة الأولى، ولا تُمنح شارة «موثوق» بسبب مجرد البريد/دفع رسم. لا عنوان IP كامل في جداول التطبيق؛ قد يجمع المضيف/الوكيل سجلاته، لذا يلزم ضبطها أيضًا.

## التشفير والاحتفاظ: لا تعميم مضلل

- أسرار MFA مشفرة بمفتاح التطبيق؛ النسخ الاحتياطية مشفرة AES-GCM بمفتاح مستقل.
- **قاعدة SQLite وملفات الصور على القرص ليست مشفرة بالكامل بواسطة التطبيق.** صلاحيات Linux هي 0700 للمجلد الخاص و0600 للقاعدة والملفات الحساسة. للإنتاج راجع تشفير القرص/الحجم لدى المضيف والوصول للمضيف والنسخ. chmod ليس تشفيرًا، وسلوك ACL على Windows مختلف ولم يُعتمد هنا.
- مفتاح الإنتاج لا يدخل الأرشيف؛ احتفظ بنسخة استعادة خاصة مستقلة عنه. مفتاح التطوير يُضمّن داخل الأرشيف المشفر لتمكين الاستعادة المحلية.
- النسخ المدورة تحتفظ افتراضيًا 14 يومًا **كسياسة مثال تشغيلية**؛ اختيار المدة يجب أن يناسب القانون والعقود وRPO/RTO. هذا لا يضع مدة قانونية للسجلات الحية.
- لا يوجد حاليًا purge مجدول شامل لبيانات الحساب/البريد/سجلات الأعمال أو آلية انتشار حذف عبر النسخ. يجب اعتماد سياسة مدد وإجراء إتلاف/حجز قانوني قبل الإنتاج. لا تحذف أحداث مالية لإخفاء أثر.

## تصدير وحذف الحساب

**لا يوجد زر تصدير/حذف ذاتي أو مسار API يحقق ذلك الآن.** لا تعلن أنه منفذ. في إطلاق محدود بعد المراجعة القانونية يحتاج المشغّل إجراء طلب يدوي موثق:

1. وسيلة اتصال حقيقية ومعلنة باسم مسؤول البيانات، لا بريد وهمي أو نموذج لا يرسل.
2. التحقق من صاحب الحساب بطريقة مناسبة، دون طلب كلمة مروره أو رمز MFA في الدعم.
3. تحديد نطاق البيانات الخاصة به، وحماية بيانات عملاء/بائعين آخرين؛ إنشاء تصدير خاص وآمن ومؤقت وتسليم موثق. هذا تشغيل مخصص وليس أمرًا آليًا جاهزًا في هذه النسخة.
4. تقييم الطلبات القائمة، حقوق أطراف أخرى والتزامات الحفظ القانونية بمراجعة المختص؛ تعطيل الدخول وحده **ليس حذفًا**.
5. حذف/إخفاء ما يجوز قانونًا بترحيل مدروس واختبار، والإبقاء على سجل الإجراء دون أسرار، مع بيان متى تنتهي نسخ تحتوي البيانات؛ إعادة تطبيق قرارات الحذف عند الاستعادة.

تستلزم الخدمة الذاتية وقواعد الإخفاء/الحفظ تطويرًا لاحقًا واختبارات. لا تنفذ `DELETE FROM users` عشوائيًا في قاعدة إنتاج مترابطة أو تتجاوز triggers التدقيق.

## قائمة إلزامية قبل استقبال بيانات حقيقية

- [ ] نطاق HTTPS عام صحيح، secure cookies، أسماء مضيف محددة، ومنع الوصول العام إلى منفذ التطبيق/البيانات.
- [ ] مضيف محدث ومحدود المستخدمين، شفرة/venv للقراءة فقط لمستخدم الخدمة، جدار ناري، أسرار خارج Git وstatic، وMFA لحسابات الإدارة الخارجية.
- [ ] SMTP فعلي واختبار وصول في AR/EN، ضبط DNS والسياسة والاحتفاظ بطابور/رسائل البريد، وعدم تسجيل روابط reset/verify في الوكيل/المراقبة.
- [ ] نسخة مشفرة يومية فعلية خارج الجهاز، مفتاح استعادة مستقل، تنبيه فشل وتمرين استعادة مع توثيق RPO/RTO.
- [ ] مراجعة مختص أردني للخصوصية والتجارة الإلكترونية وحماية المستهلك والضرائب والسلع المقيدة، واتفاق البائع والتحصيل والشحن والعمولة والنزاع/الإرجاع قبل البيع. لا تفترض أن إيصال الموقع فاتورة رسمية.
- [ ] اعتماد سياسة حساب/حذف/تصدير ومدد ووسيلة اتصال واقعية وإجراء حوادث؛ المسودات ليست قبولًا قانونيًا كافيًا.
- [ ] فحص أمان خارجي مناسب للحجم، ومراجعة وصول الموظفين وفصل أدوار الموافقات عند إضافة صرف حقيقي.
- [ ] مراجعة يدوية للإتاحة بقارئات شاشة وهواتف/متصفحات مستهدفة؛ نجاح axe وحده لا يثبت كل WCAG 2.2 AA.

## الأسرار القديمة والحوادث

إزالة `.env` من شجرة Git الحالية **لا تمحو تاريخ Git أو النسخ الأخرى**. بدّل أي سر حقيقي استُخدم سابقًا وظهر علنًا، ولا تعِد استخدام كلمات/قيم الأمثلة القديمة. لم نُعد كتابة تاريخ المستودع.

عند الاشتباه: اعزل الخدمة/الحساب المتأثر، احفظ الأدلة بأقل بيانات وبوصول مقيد، أبطل الجلسات وغيّر الأسرار المتأثرة، حدد نطاق الأثر، وطبّق متطلبات إخطار الجهات/الأشخاص مع المختص وفق القانون. لا تدع AI يقرر الاحتيال أو الصرف نهائيًا، ولا تُنشئ سجلات عامة تحتوي بيانات التسليم أو كلمات المرور أو QR أو رموز البريد.
