في 2026-10-28 أضيف WSGI اختياري بـa2wsgi 1.10.10 وملفات إعداد PythonAnywhere، مع إبقاء Uvicorn/ASGI هو المسار المعتاد. لا حساب خارجي أُنشئ أو رُبط، ولا رابط عام جديد ثبت تشغيله.

- `bash tests/run.sh`: **99 passed**، تحذير TestClient نفسه، **34.27 ثانية**؛ تغطية **92.15%** (1656 تعليمة، 130 غير مغطاة)، وحد 90% ناجح. التقرير المحلي `data/backend-free-deployment.txt`.
- 12 حالة إضافية في `tests/test_wsgi_deployment.py`: WSGI/HTTP، AR/EN وstatic/PWA، CSRF/ملكية/صور، Secure cookie على HTTPS حتى للمعاينة، طلب متجرين وتكراره واستمرار ملفاته/مخزونه بعد إعادة إنشاء التطبيق، حد الجسم، whitelist journal mode، وتأخير إنشاء loop إلى أول طلب وتجديده عند اختلاف PID حتى لا يرث worker خيطًا ميتًا بعد fork، وإعداد خاص idempotent لا يمسح البيانات ولا يستبدل env مختلفًا أو يقبل نطاق حساب آخر.
- ASGI/WAL: **6/6** متصفح، صفر unexpected/skipped/flaky، **66.257 ثانية**، `data/browser-asgi-free-deployment.json`.
- WSGI/DELETE: **6/6** متصفح، صفر unexpected/skipped/flaky، **70.237 ثانية**، `data/browser-wsgi-free-deployment.json`. نفس سيناريوهات الشراء/البائع/MFA/رفع الصور/المخزون/العمولة والإتاحة/offline، وليست صور واجهة فقط.
- روابط تأكيد/إعادة كلمة المرور الجديدة تحمل fragment لا query؛ اختُبرت قراءة الرابط الجديد، التوافق مع القديم، إزالة الرمز من شريط العنوان، وتبديل اللغة دون ضياع النموذج ثم التأكيد الفعلي. السلوك لا يستهلك الرمز على GET.
- Service Worker **`shamaa-public-v1.0.3`**، مع إعادة جلب القشرة عند تثبيت cache جديد، واستمرار نجاح استثناء الخاص ورفض الكتابة offline على النقلين.
- `pip-audit --require-hashes -r requirements-pythonanywhere.lock`: **لا ثغرات معروفة مرصودة** وقت الاختبار؛ npm audit: **0**؛ pip check وNode syntax نجحت. فحص الحزم ليس اعتماد مضيف/نظام تشغيل أو اختبار اختراق.
- CI عُدّل لتكرار browser job على ASGI وWSGI؛ نجاحه الفعلي على GitHub لا يُفترض قبل نتيجة هناك.

**حد التحقق:** هذه اختبارات محلية وليست اختبار شبكة ملفات PythonAnywhere أو uWSGI/الصورة/الحصص في حساب حقيقي. الحساب وWeb/virtualenv/WSGI/Reload والاختبار الخارجي وTLS وتسليم SMTP والنسخ المؤتمت/الخارجي لم تنفّذ. الخطة المجانية مرشح لمعاينة فقط بحدودها، ولا تنفذ systemd/crons أو تطلق بيعًا حقيقيًا من تلقاء نفسها. ## سجل النسخة السابقة قبل إضافة مسار WSGI

الأقسام أدناه توثق تشغيل المرحلة الأولى السابق، وليست ادعاء أن رابط معاينة Arena القديم ما زال صالحًا أو نشرًا خارجيًا.

## البيئة

- Linux، Python 3.11.2 داخل `.venv`، Node 22.22.3.
- FastAPI 0.162.0، Starlette 1.10.0، Uvicorn 0.54.0، Pillow 13.0.0، cryptography 50.0.2، python-multipart 0.0.32.
- Playwright 1.64.1، axe-core/playwright 4.14.0، Chromium 153 من حزمة npm `@sparticuz/chromium`، مع حذف flags مثل `--disable-web-security` و`--allow-running-insecure-content` و`--single-process` من إعداد الحزمة الافتراضي. لا يُقدّم هذا المتصفح كبيئة hardened معتمدة.
- قفل runtime وقفل development شاملان بالبصمات على Linux/Python 3.11. لا إثبات توافق Windows/macOS/كل إصدارات Python من هذا التشغيل.
- مخطط SQLite v1، Service Worker cache `shamaa-public-v1.0.2`.

## 2. اختبارات المتصفح الكاملة على النسخة النهائية

```bash
SHAMAA_BUNDLED_BROWSER=1 npx playwright test --reporter=json
```

آخر تشغيل بدأ **16:59:13 UTC**؛ المدة **80.703 ثانية**. **6 ناجحة من 6، صفر فشل/تخطٍ/اختبارات flaky** في تقرير هذا التشغيل، دون retries معدّة. التقرير المحلي `data/browser-report.json` خارج Git.

1. **واجهتا AR/EN:** RTL/LTR، بحث وفرز ومتاجر، مفضلة محلية، حوار دخول بلوحة المفاتيح، وفحص axe في اللغتين والحوار، دون أخطاء pageerror.
2. **هاتف 390px:** سلة زائر من متجرين ثم دخول ودمج، checkout محسوب وشحنان وCOD، حفظ بعد reload، وإلغاء شحنة. فحص axe للتأكيد والطلبات.
3. **بائع/مشرف فعليان بالاختبار:** طلب متجر وموافقة مدير بمصادقة TOTP، صورة مرفوعة ومنتج ومراجعة ونشر ومخزون، صفحة متجر، إعداد عمولة فئة وحفظها وإعادة تحميلها وتبديل الفئات دون إخفاء النسبة السابقة. axe لصفحة متجر وإعدادات.
4. **البريد:** تسجيل مستخدم عشوائي وقراءة `.eml` خاصة من الخادم المعزول، فتح الرابط دون استهلاكه على GET ثم تأكيد POST. لا SMTP خارجي في هذا السيناريو.
5. **PWA/offline:** انتظار cache العام، منتج محمل يعمل عند قطع الشبكة، رفض إضافة/كتابة دون اتصال وعدم تغير المخزون، وعدم وجود مسارات حساب/طلب/إدارة/وسائط في cache العامل الخدمي، وصفحة خاصة offline.
6. **إتاحة وتجاوب:** 320/768/1024px، 390px للبحث، نص 200% وتركيز مرئي، دون overflow أفقي في القياسات المختبرة.

الخادم يُدار على 8011 بقاعدة `data/browser-tests/` فقط، وكلمات مرور/مفاتيح/بريد وصورة مولّدة عند التشغيل. لا حسابات اختبار أو كلمات مرور ثابتة منشورة. يُغلق الخادم المعزول عند انتهاء المجموعة؛ بياناته ليست بيانات المتجر على 8000.

**axe لم يجد مخالفات في الفحوص المختارة**. لا يختبر كل معيار WCAG 2.2 AA أو كل صفحة/حالة/قارئ شاشة؛ لا ندّعي شهادة شاملة أو اختبار Safari/Firefox/iOS/Android فعلي.

تدقيق حزم سليم اليوم لا يعني خلو التطبيق أو نظام التشغيل أو المضيف من ثغرات، ولا يثبت سلامة كل مورد/موافقة تجارية. يلزم تكراره مع التحديثات.

## ما لم يُختبر/يُفعّل خارجيًا

- نشر إنتاج، DNS أو شهادة HTTPS أو تجديدها، وضبط Nginx/systemd على مضيف خارجي.
- وصول SMTP إلى صندوق حقيقي أو deliverability/ارتداد/حصة مزود.
- جدولة نسخ حقيقية وتنبيهها/تخزين خارج الجهاز وتمرين استعادة تشغيلي؛ اختبارات الاستعادة المحلية موجودة فقط، مع أداة وقوالب الأتمتة.
- بوابة دفع/تحصيل أو صرف أو ناقل أو محاسبة/ضرائب أو AI. ليست خدمات مفعّلة مخفية خلف تصميم.
- تصدير/حذف ذاتي، اعتماد سياسات قانونية أردنية، فواتير رسمية أو تراخيص نشاط.
- اختبار حمل/RPO/RTO/اختراق مستقل/شهادة إتاحة/عمل كل متصفح وهاتف.

**الخلاصة:** الأساس التقني للمرحلة الأولى قابل للتشغيل واختُبرت التدفقات المذكورة. توجد بوابة إطلاق إنتاج منفصلة في [PHASES.md](PHASES.md) و[OPERATIONS.md](OPERATIONS.md)؛ لم تُجتز نيابة عن المالك.
